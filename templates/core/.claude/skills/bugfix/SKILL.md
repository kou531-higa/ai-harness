# /bugfix：不具合修正

対象：$ARGUMENTS

## 手順

1. **判定する**：`gh issue view` でチケットを読み、仕様（`docs/specs/`）と照らして判定し、チケットにコメントする。
   - 仕様どおりに動いていない → 続ける
   - 仕様そのものの問題 → 止めて人へ戻す
2. **再現テストを書く**：ブランチ `fix/<番号>-<説明>` を切り、`tests/regression/` に再現テストを書く。
   テスト名にチケット番号を入れる（例：`test_bug_123_...`）。
   実行して**修正前のコードで落ちること**を確かめ、そのログをチケットに貼ってコミットする。
3. **原因を特定する**：原因と根拠（コード・ログ・データ）をチケットに書く。エラーを握りつぶさない。
4. **直す**：再現テストを通し、`make check` で周辺のテストもすべて通す。
   同じ書き方がほかにないか `grep` で探し、あれば一緒に直すか、チケットに書く。
5. **PR を作る**：`gh pr create`。「修正前に落ちたテストのログ（または CI のリンク）」を必ず貼る。

## 終わってよい条件

- 再現テストが修正前に落ち、修正後に通っている
- 原因の説明に根拠がある
- `make check` が通っている

## 止まって人へ戻す条件（/decision-memo、ラベル ai-stop:<理由>）

| 状況 | 理由 |
|---|---|
| 原因が仕様の未確定、または仕様の問題 | `spec-undecided` |
| 本番データの補正が必要 | `irreversible` |
| 修正前のコードでも再現テストが通ってしまう（再現できない） | `other`（チケットに needs-info を付けて起票者へ戻す） |
| 同じ問題を2回直しても解決しない | `two-failures` |

## してはいけないこと

- 再現テストなしで直す
- 例外を握りつぶして症状だけ消す
- データの補正をコードの修正と同じ PR に入れる
