# /bugfix：不具合修正

対象：$ARGUMENTS

## 手順

1. **判定する**：`gh issue view` でチケットを読み、仕様（`docs/specs/`）と照らして判定し、チケットにコメントする。
   - 仕様どおりに動いていない → 続ける
   - 仕様そのものの問題 → 止めて人へ戻す
   - もう直っている（main で再現しない） → 直した PR か変更を探し、証拠（再現の手順と結果・直した PR）をコメントして閉じ、そこで終える。人に「閉じてよいか」と聞いて止まらない
   **関係する決定を集める**：チケット・仕様・PR の本文とコメントに出てくる `#番号` のうち、判断チケット（`needs-decision`）を `gh issue view` で読み、閉じたものは最後の「決定：」のコメントを、開いているものは「判断待ち」として並べる。決まりの一覧（`docs/decisions/rules.md`）で当てはまる R-ID も並べる。この一覧を計画（PR の本文）の最初に「関係する決定」として書き、それに反することはしない。開いている判断待ちに関わる所は、決まるまで進めない。
   **決定を書き戻す**（着手の前に）：チケットのコメントにある決定（「〜にする」「〜で合意」など）は、判断記録（`docs/decisions/DEC-xxx`、型は `_template.md`）か仕様に書き戻してから実装する。**コメントは正本にしない**（あとから読む AI と人が読み落とすため）。書き戻すまで実装を始めない。仕様を変えるときは、変えた行を PR の「人が判断すべき点」に挙げる。
2. **今の振る舞いを固定する**：直す所のまわりにテストがなければ、不具合以外の今の振る舞いを確かめるテストを先に書いて通しておく。
   直したことで、別の所が変わっていないことを確かめるため。テスト名は `char_<対象>`。範囲は `/impact` で出す。
3. **再現テストを書く**：ブランチ `fix/<番号>-<説明>` を切り、回帰テストの場所に再現テストを書く。
   テスト名にチケット番号を入れる（例：`bug_123`）。
   実行して**修正前のコードで落ちること**を確かめ、そのログをチケットに貼ってコミットする。
4. **原因を特定する**：原因と根拠（コード・ログ・データ）をチケットに書く。エラーを握りつぶさない。
   同じ判定や書き方が、画面・API・バッチ・プロシージャのほかの場所にもないか `/impact` で探し、あれば一覧にする。
5. **直す**：再現テストを通し、`make check` で周辺のテストもすべて通す。
   状態の判定が原因なら、直接書かずに `catalog/` の定義を使う形に寄せる。
6. **決定記録を1本書く**（必須）：この変更で決めたことを、`docs/decisions/_template.md` の型で `docs/decisions/DEC-<番号>-<短い名前>.md` に書く。中身は、なぜ・合意した範囲・先送りしたものと理由・根拠（仕様の版・元の位置）。番号を PR の「関係する DEC」に書く（CI が、参照した DEC のファイルがあるか確かめる）。直し方を選んだ理由と、今回は直さなかった所（ほかの場所の同じ書き方など）も、ここに書く。
7. **PR を作る**：`gh pr create`。「関係する DEC」と「修正前に落ちたテストのログ（または CI のリンク）」を必ず書く。
   1チケットを分けるときも、積み重ねにせずそれぞれ main から作る。前の PR の枝から切らない。分割の途中ではチケットを閉じない。最後の PR だけ `Closes #番号`、ほかは `Refs #番号` と書く。

## 終わってよい条件

- 再現テストが修正前に落ち、修正後に通っている
- 今の振る舞いを固定するテストも通っている
- 原因の説明に根拠があり、ほかの場所の同じ書き方を一覧にしてある
- `make check` が通っている
- 決定記録が1本あり、PR の「関係する DEC」に番号がある。チケットのコメントにだけある決定が残っていない

## 止まって人へ戻す条件（/decision-memo の型で判断チケットを起票する。ラベル ai-stop:<理由>）

| 状況 | 理由 |
|---|---|
| 原因が仕様の未確定、または仕様の問題 | `spec-undecided` |
| 直し方によって、顧客から見える結果が変わる | `customer-agreement` |
| 本番データの補正が必要 | `irreversible` |
| 修正前のコードでも再現テストが通ってしまう（再現できない） | `other` |
| 同じ問題を2回直しても解決しない | `two-failures` |

## してはいけないこと

- 再現テストなしで直す
- 例外を握りつぶして症状だけ消す
- データの補正をコードの修正と同じ PR に入れる
- チケットのコメントにだけある決定に従って直す（先に判断記録か仕様に書き戻す）
