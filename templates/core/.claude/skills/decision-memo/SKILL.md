# /decision-memo：判断メモ

論点：$ARGUMENTS

## 手順

1. **過去の決定を探す**：`docs/decisions/` と、`needs-decision` ラベルの閉じたチケットを検索する。
   同じ論点の決定があれば、それに従い、起票しない。
2. **決定者を選ぶ**：`docs/decisions/owners.md`（決定者マップ）から、判断の種類に合う決定者と期限を選ぶ。
   例：仕様・業務の扱いは顧客、技術の選択はテックリード。マップにない種類なら「決定者：未定」と書き、PM に選んでもらう。
3. **判断メモを書く**：下の型で書く。スマホで1画面に収まる長さにする。
4. **起票する**：
   ```
   gh issue create --title "判断：<論点>" --label needs-decision --label "ai-stop:<理由>" --body-file <メモ>
   ```
   ラベルがなければ `gh label create` で作る。顧客の合意が要るものは `ai-stop:customer-agreement` にする。
5. **元の場所からリンクする**：仕様の未確定なら、その行に `decision: #<番号>` を書く。
   PR やチケットなら、コメントで判断チケットへリンクする。
6. **待つ**：決定が出るまで、その論点に関わる実装はしない。
7. **決定を反映する**：決定がコメントで出たら、仕様と判断記録（必要なら ADR）を更新する PR を作る。
   同じ種類の判断が今後も出そうなら、判断の基準をルールにする案（/harness-rule）も添える。

## 判断メモの型

```
## 論点
<何を決めるか。1〜2行>

## 選択肢と影響
- 案1 <内容>：工数 <x日>／<戻せる・戻せない>／<リスク>
- 案2 <内容>：工数 <x日>／<戻せる・戻せない>／<リスク>
- 案3 <内容>：…（あれば）

## 推奨
案<n>。根拠：<1〜3行>

## 決定者と期限
決定者：@<名前>　期限：<日付>（既定は2営業日後）

## 関連
<仕様・PR・チケットへのリンク>
```

## 終わってよい条件

- 論点・選択肢・影響・推奨の4項目がすべて埋まっている
- 戻せない選択肢には、そう明記してある
- `needs-decision` と `ai-stop:<理由>` のラベルが付いている

## 止まって人へ戻す条件

- 選択肢を出せるだけの情報がない → 選択肢の代わりに「判断に必要な情報を取りに行く質問」を書いて起票する
