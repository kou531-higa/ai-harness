# /impact：影響範囲の一覧

変えたいこと：$ARGUMENTS

## 手順

1. **言葉を選ぶ**：変えたいことに出てくる状態名・テーブル名・列名・関数名・取引先コード・画面ID を、実装の書き方で3〜8個選ぶ
   （例：`ON_HOLD`・`maintenance_paid`・`sp_close_monthly_billing`・`SCR-005`）。
2. **機械で探す**：`python3 scripts/impact.py <言葉...>`。層ごとの件数と「テストなし」の層を確かめる。
3. **1段たどる**：当たった関数・SQL・API を呼んでいる所を、その名前でもう一度探す（画面 → API → SQL・プロシージャ → バッチ）。
   同じ判定が別の書き方で書かれていないかも探す（例：状態の一覧を文字列で並べている所）。
4. **分ける**：当たった所を1件ずつ読み、次のどれかに分ける。読んでいない所は「未確認」と書く。
   - **変える**：この変更で直す所
   - **確かめる**：変えないが、結果が変わるかもしれない所（テストで確かめる）
   - **関係なし**：言葉は同じだが別の意味（理由を1行）
5. **テストのない所を出す**：「変える」「確かめる」なのにテストがない所を並べ、今の振る舞いを固定するテストを書く所として示す。
6. **返す**：下の表を、チケットか PR の計画のコメントに貼る。

## 返す形

```
## 影響範囲：<変えたいこと>
言葉：…　探したコマンド：python3 scripts/impact.py …

| 層 | 場所 | 分類 | 理由 | テスト |
|---|---|---|---|---|
| db | db/procedures/xxx.sql:12 | 変える | … | なし → 固定するテストを書く |

### 未確認・未カバー
- …
```

## 終わってよい条件

- 当たった所がすべて「変える・確かめる・関係なし・未確認」のどれかに分かれている
- 「変える」「確かめる」の所に、テストがあるか、固定するテストを書く予定が書いてある
- 探した言葉とコマンドが書いてある（人がやり直せる）

## 止まって人へ戻す条件

- 同じ判定が複数の層で違う書き方になっていて、どれが正しいか仕様で決まらない → `ai-stop:spec-conflict`
- 共通部品・カタログ・DB の構造を変えないと直せない → `ai-stop:shared-component`
- 「変える」が400行に収まりそうにない → 分割案を出して `ai-stop:pr-too-large`
