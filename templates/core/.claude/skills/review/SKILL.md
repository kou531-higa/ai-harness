# /review：AI レビュー

対象：$ARGUMENTS

## 手順

1. **PR を手元に**：`gh pr checkout <番号>`。基準は `gh pr view <番号> --json baseRefName` の `origin/<ブランチ>`。
   この会話でその PR を書いていたなら、`/clear` してから始める（書いた考えに引きずられるため）。
2. **割り振る**：`python3 scripts/review_route.py --base origin/<ブランチ> --json`。
   `--generic` のときは、担当を `general` の1体だけにして、すべてのファイルを渡す（担当別と比べるため）。
3. **並行で読ませる**：割り振られた担当ごとに、サブエージェント `reviewer` を1体ずつ、同時に起動する。渡すのは次だけ。
   - 観点の一覧 `.claude/review/<担当>.md`
   - その担当のファイルの一覧と基準
   - 関係する仕様の ID（PR の本文やチケットにあれば）
   PR の説明・書いた人の考え・ほかの担当の結果は渡さない。
4. **合わせる**：同じ場所の指摘は1件にまとめ、重い方の重さと、見つけた担当をすべて書く。根拠のない指摘は落とす。
5. **未カバーを並べる**：次の3つを1つの節にする。
   - どの担当にも割り振られなかったファイル（`uncovered`）
   - レビュー役が「未カバー」「見ていない」と返した所
   - 重要な所の変更（`critical_changed`）：AI が見ても、人も見る
6. **コメントする**：下の型で `gh pr comment <番号> --body-file <ファイル>`。
7. **記録する**：`.harness/reviews/pr-<番号>.json` に、担当・重さごとの件数・未カバーの件数・`--generic` かどうかを書く（あとで集計する）。

## コメントの型

```
## AI レビュー（担当：api・security・state ／ 汎用：いいえ）

### 必須 n件
| 場所 | 内容 | 見つけた担当 | 直し方の案 |
### 推奨 n件
### 細かい n件

### 未カバー（人が見る所）
- 割り振りなし：…
- レビュー役が確かめられなかった所：…
- 重要な所の変更：…
```

## 終わってよい条件

- 割り振られた担当がすべて結果を返し、合わせた結果が PR にコメントしてある
- 未カバーの節がある（0件なら「なし」と書く）
- `.harness/reviews/pr-<番号>.json` がある

## 止まって人へ戻す条件

- 重要な所が未カバー（割り振りなし、またはレビュー役が見られなかった） → `ai-stop:uncovered`
- 必須の指摘が、仕様の未確定や食い違いから来ている → `ai-stop:spec-undecided`／`ai-stop:spec-conflict`

## してはいけないこと

- レビューの中でコードを直す（直すのは別の作業。書いた側に戻す）
- PR を承認・マージする
