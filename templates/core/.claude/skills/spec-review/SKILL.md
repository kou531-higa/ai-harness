# /spec-review：仕様のレビュー

仕様：$ARGUMENTS

## 手順

1. **何回目かを見る**：`.harness/reviews/spec-<仕様のID>.json` があれば2回目から。前回の指摘の台帳（番号・重さ・状態）と、前回見たコミットを読む。
   2回目からは、**前回からの差分と未解決の指摘だけ**を見る（`git diff <前回のコミット> -- <仕様>` と、未解決の指摘の場所）。
2. **機械で数える**：
   ```
   python3 scripts/check_undecided.py $ARGUMENTS
   python3 scripts/check_spec_consistency.py docs/specs --baseline docs/specs/consistency-baseline.json
   python3 scripts/check_dec_refs.py $ARGUMENTS
   ```
3. **別の目で読む**：サブエージェント `spec-reviewer` に、仕様のパスだけを渡してレビューさせる（前景で動かし、結果が返るまで待つ）。
   2回目からは、前回からの差分と、未解決の指摘（番号・場所・内容）も渡す。
   自分の考えや答えの候補は渡さない（引きずられるため）。
4. **合わせる**：2 と 3 の結果を1つの表にする。同じものは1件にまとめ、どちらで見つかったかを書く。
   下の「収束の決まり」で、番号を振り、状態を付け、上限で絞る。
5. **台帳を作り直す**：`python3 scripts/undecided_ledger.py`。印のない未確定（「など」「適宜」）は台帳に載らないので、
   仕様の該当の行に「要確認」と印を付けてよいか人に聞く。
6. **人に返す**：表と、決定者ごとの質問の一覧を出す。決定者ごとに、`/decision-memo` の手順と型で判断チケットを起票する（起票はしてよい。決めるのは人）。
7. **記録する**：`.harness/reviews/spec-<仕様のID>.json` に、回数・見たコミット・指摘の台帳・重大な新規の件数を書く。

## 収束の決まり

- **指摘に番号を振る**：`S1-2`（1回目の2件目）の形。次の回では、前の番号ごとに **解決・見送り・新規** のどれかを付けて追う。見送りには理由を書く
- **重さの下限**：重大にしてよいのは、正しさ（決めないと実装できない・結果が変わる）・仕様の矛盾・セキュリティ（個人情報を含む）だけ。言い回しや書き方の好みは指摘にしない
- **1回の指摘の上限**：10件まで。超えるときは重い順に10件を載せ、残りは件数だけ書く
- **閉じる条件**：**重大な新規が0の回が2回続いたら閉じる**。閉じたら「仕様のレビューを閉じます」と書き、それ以上回さない
- **差分の外の気づき**：今回の差分の外（ほかの仕様など）で見つけたことは、作業チケットにして番号だけ書く。この仕様の必須にしない

## 終わってよい条件

- 2 と 3 の両方を実行し、合わせた表がある
- 1件ごとに番号・場所と、誰に何を聞くかが書いてある。前の指摘すべてに状態が付いている（2回目から）
- 未決事項台帳が作り直してある（`python3 scripts/undecided_ledger.py --check` が通る）

## 止まって人へ戻す条件

- 未確定や食い違いが1件でもある → 実装に進まない。表を返して止まる（`ai-stop:spec-undecided` または `ai-stop:spec-conflict`）
- 仕様レビュー役が「未カバー」を返した → その範囲を人に伝える
