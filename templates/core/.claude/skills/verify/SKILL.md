# /verify：動くまで試す

確かめたいこと：$ARGUMENTS

## 手順

1. **検査**：`make check`。落ちたら直してやり直す。
2. **起動**：`make up`。起動しなければ `make logs` で原因を読む。
3. **データ**：`make migrate` → `make seed`。マイグレーションを足したなら、空の DB から通ることも確かめる。
4. **画面のテスト**：`make e2e`。
5. **実際の操作**：確かめたいことを、人がする操作のとおりに動かす（API を呼ぶ、バッチを流す、画面を開く）。
   AC の Given／When／Then の Then を、出力や DB の中身で確かめる。
6. **証拠を残す**：実行したコマンドと出力（長ければ要点と件数）を、PR の「証拠」に貼る。
7. **片付ける**：`make down`。

## 失敗したとき

- 直す前に、失敗の原因を1行で書く（推測なら「推測」と書く）
- 1回直すごとに、どこまで通ったかを書く
- **同じ失敗が2回続いたら止まる**：試したことと、それぞれの結果を `/decision-memo` の型で判断チケットに書いて `ai-stop:two-failures`
- テストを消す・skip する・待ち時間を延ばすだけ、で通さない

## 終わってよい条件

- 1〜5 がすべて通り、6 の証拠がある
- 確かめられなかったこと（外部のサービス、本番だけのデータなど）を「未確認」として書いてある

## 止まって人へ戻す条件

- 同じ失敗が2回続いた → `ai-stop:two-failures`
- 確かめるのに本番のデータや設定が要る → `ai-stop:irreversible`
