# CLAUDE.md

AI と人の共通の規約。毎回の会話で読み込まれるので、**消したら AI が間違える行だけ**を書く（150行以内）。
手順はスキル（`.claude/skills/`）、必ず起きるべきことはフック（`.claude/settings.json`）、
層ごとの作法は各ディレクトリの `CLAUDE.md` に置く。

## 1. このプロジェクト

## 2. 決めないこと（人へ戻す）

次の場合は作業を止め、人へ戻す。推測で埋めない。

- 仕様に TBD・要確認・保留・TODO・確認待ち・書きかけ が残っている、または仕様どうしが食い違う
- 顧客の合意が要る（業務の扱い、表示や帳票の変更、顧客との約束に関わる）
- 同じ問題を2回直しても解決しない
- セキュリティ・個人情報に関わる判断
- 戻せない操作（本番の設定、データの削除や補正、適用済みのマイグレーション）
- レビューで、重要な所が「未カバー」になった

決まりの一覧（`docs/decisions/rules.md`）で答えが出る論点は戻さず、決まりに従って ID を PR と仕様に書く。
決定の正本は、判断記録（`docs/decisions/DEC-xxx`）と仕様だけ。チケットのコメントは正本にしない。コメントの決定は、書き戻してから使う。
戻すときは `/decision-memo` の手順と型（論点／選択肢1〜3／影響／推奨）で、判断チケットを `gh issue create` で起票する。起票は AI がしてよい（決めるのは人）。
ラベル `ai-stop:<理由>` を必ず付ける。理由は次から選ぶ：
`spec-undecided` `spec-conflict` `customer-agreement` `two-failures` `shared-component`
`pr-too-large` `irreversible` `security` `uncovered` `other`

## 3. 書いてよいもの・書かないもの

- 書かない：ログ・入力チェック・エラーの返し方・SQL の組み立て・ページング・トランザクション・テストの土台。
  共通部品（`api/src/common/`・`web/src/lib/`・`batch/core/`）を使う
- 状態の判定（「取り消せる注文か」など）を直接書かない。`catalog/` の定義と、そこから作った関数を使う
- 共通部品やカタログの追加・変更が必要なら、まず判断チケットで人に認めてもらう（`ai-stop:shared-component`）。
  認められたら、AI がテストを先に書いて共通部品だけの PR を作る（機能の変更と混ぜない）。人はマージで確かめる（人が書くのではない）
- テストを消す・skip する変更は、理由を書いて止まる

## 4. ブランチと PR

- ブランチ名：`feat/<チケット番号>-<短い説明>`、`fix/<チケット番号>-<短い説明>`
- 1PR＝1チケット。変更は本体（テストを除く）400行・テスト800行以内（超えそうなら分割案を出して止まる）
- 1チケットを分けるときも、積み重ねにせずそれぞれ main から作る。分割の途中ではチケットを閉じない
- PR はテンプレートの「人が判断すべき点」と「証拠」を必ず埋める
- マージはしない。main へ直接 push しない（人が `make merge PR=<番号>` でマージする）

## 4-2. 並べて進める（git worktree）

作業場所（git worktree）を分けて、複数のチケットを同時に進めるとき（詳しくは `docs/harness/parallel.md`）：
- fetch は親が1回だけ。各作業の中では fetch・pull しない（`.git` を共有していて取り合うため）
- PR とチケットは、自分のブランチ名（`gh pr list --head <ブランチ>`）と自分が起票した番号で絞る。ほかの作業のものに触らない
- 手元で起動するときは、公開ポートを作業場所ごとの `.env` でずらす
- マージは1本ずつ順に。1本マージしたら、残りは main に合わせ直してから次へ

## 5. テスト

- 合格基準（AC）ごとにテストを書く。テスト名に AC の ID を入れる（例：`ac_001_1`）
- テストを先に書き、落ちることを確かめてから実装する
- テストのない所を変えるときは、変える前に「今の振る舞いを固定するテスト」を書く
- 画面のテストは、固定の秒数ではなく画面の状態を待つ。要素は役割か testid で取る

## 6. 確かめ方と終わり方

- 終わる前に `make check` を実行し、コマンドと出力を示す。「通った」とだけ書かない
- 動きの変更は、手元で起動して確かめる（`make up` → 画面のテスト）
- 本番は読み取り専用ロールだけ。apply・マージ・本番データの変更はしない
- 1つのチケットが終わったら `/clear` する
- 人と話さずに動かす（`claude -p`）ときの決まりは `docs/harness/headless.md`
