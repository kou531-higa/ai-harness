# 並べて進める（git worktree）

作業場所（git worktree）を分けて、複数のチケットを同時に進めるときの決まり。
worktree どうしは `.git` を共有している。だから、取り合い（fetch）と取り違え（ほかの作業の PR やチケット）が起きる。

## 1. fetch は親が1回

- `git fetch` は、並べる前に親（全体を動かす人か台本）が1回だけ行う
- 各作業の中では、fetch・pull をしない。基準は親が取った `origin/main` を使う
- 作業の途中で main が進んだときも、親が fetch してから、各作業に合わせ直しを頼む

## 2. 自分のものだけで絞る

- PR は、自分のブランチ名で絞る：`gh pr list --head <自分のブランチ>`、`gh pr view <自分のブランチ>`
- チケットは、自分が扱っている番号と、その実行で起票した URL だけを使う。「最新の PR」「最新のチケット」で探さない
- ほかの作業の PR・チケット・ブランチに、コメントや変更をしない

## 3. 手元の公開ポートをずらす

同じ機械で同時に起動すると、公開ポートがぶつかる。ポートを環境変数にして、作業場所ごとの `.env` でずらす。

`docker-compose.yml`（例。導入先の形に合わせる）：

```yaml
services:
  web:
    ports:
      - "${WEB_PORT:-3000}:3000"
  api:
    ports:
      - "${API_PORT:-8080}:8080"
  db:
    ports:
      - "${DB_PORT:-5432}:5432"
```

作業場所ごとの `.env`（コミットしない）：

```
COMPOSE_PROJECT_NAME=wt-123   # コンテナとボリュームの名前も分ける
WEB_PORT=3100
API_PORT=8180
DB_PORT=5532
```

- 中の番号（右側）は変えない。外に出す番号（左側）だけをずらす
- 画面のテストや API のテストの行き先も、同じ環境変数から作る（番号を直接書かない）

## 4. 触るファイルを分ける

- 並べる前に、チケットごとに「触る予定のファイル」を出す。重なるものは同じ回に並べず、順にする
- 共通部品・カタログ・マイグレーションを触るチケットは、並べない
- 一覧や目次の同じ1行に、それぞれが名前を書き足す形にしない。並べると、触るファイルが別に見えても、その1行で必ず衝突する。次のどちらかにしておく
  - 1項目1行にする（例：Makefile の `.PHONY` は、目標ごとにその直前に1行ずつ書く）
  - 一覧を自動で作る（例：サイトの目次を、ファイルの置き場所と見出しから作る）

## 5. マージは1本ずつ順に

- マージは1本ずつ。1本マージしたら、残りの PR は main に合わせ直し、検査が緑になってから次をマージする
- 1チケットを分けた PR も、それぞれ main から作る（積み重ねない）。分割の途中ではチケットを閉じない
- 分けた PR は、触るファイルが分かれていれば並べて進めてよい。チケットは最後の PR（`分割 n/n`）で閉じる

## 6. 衝突は先に見る

- main と衝突している PR では、GitHub は CI を動かさない。検査を待つ前に `gh pr view <番号> --json mergeable` で確かめる。`UNKNOWN` は GitHub がまだ確かめている途中なので、少し待って読み直す
- 衝突していたら、main を取り込んで直してから push する。一覧の1行の衝突は、両方の名前を残す
- 同じ直しが両方に入っている衝突（先にマージされた PR と同じ所を直した）は、main の側を採る。採ったあと、検査を手元で回してから push する
- 直したあと、検査の実行がつかないときは、失敗した実行の「再実行」ではなく新しい push（空のコミットでよい）で動かす。再実行は前の内容（PR の本文など）のまま回るため
